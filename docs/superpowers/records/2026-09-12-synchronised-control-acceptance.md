## 5-7. Аппаратная приёмка — НЕ ВЫПОЛНЕНА

Ниже — точная процедура для человека с доступом к плате и двум компьютерам.
Она переписана из раздела «Приёмка на железе» спецификации и Step 5-7 плана,
чтобы не пришлось реконструировать её заново.

### Точная процедура

1. **Прошить U1** образом `build/pico-pio-usb-release/firmware/u1_main/duo_u1_main.uf2`
   (BOOTSEL или сброс на 1200 бод — см. `duo-input-flashing-without-bootsel`).
2. **Выполнить цикл питания платы.** Это не необязательный шаг: без него хост
   не увидит ничего (0 байт в CDC), и это НЕ свидетельство о том, что прошивка
   плохая — просто прошивка без цикла питания не наблюдаема (см.
   `duo-input-power-cycle-after-flash`).
3. Открыть конфигуратор, подключиться к устройству.
4. Включить чекбокс **«Переключать клавиатуру и мышь вместе»** на странице
   настроек мыши (`self.synchronised_check`, `configurator/src/duo_input/ui/mouse.py`).
5. **Записать конфигурацию** на устройство (сохранить/применить проект — не
   просто поставить галочку в UI).
6. Пройти все восемь строк таблицы ниже по порядку, каждый раз приводя
   устройство в состояние «Было» отдельными переключениями перед тем, как
   выполнять указанное «Действие», и записать фактическое «Стало».
7. Выполнить два физических сценария (раздел ниже).
8. Выполнить сценарий с буфером обмена (раздел ниже).
9. Вписать фактические результаты в этот файл, закоммитить обновление и,
   при любом расхождении с ожиданием, вернуться к соответствующей задаче
   плана — расхождение не «мелочь на потом», а незакрытая задача.

### Таблица переходов (синхрон включён)

| Было | Действие | Стало (ожидание) | Стало (факт) |
| --- | --- | --- | --- |
| K=PC1 M=PC1 | toggle клавиатуры | K=PC2 M=PC2 | |
| K=PC1 M=PC1 | toggle мыши | K=PC2 M=PC2 | |
| K=PC1 M=PC2 | toggle клавиатуры | K=PC2 M=PC2 | |
| K=PC2 M=PC1 | toggle мыши | K=PC2 M=PC2 | |
| K=BOTH M=PC1 | toggle клавиатуры | K=PC1 M=PC1 | |
| K=BOTH M=PC2 | toggle клавиатуры | K=PC2 M=PC2 | |
| K=PC1 M=PC1 | set клавиатуры BOTH | K=BOTH M=PC1 | |
| K=BOTH M=PC1 | toggle мыши | K=PC2 M=PC2 | |

Две разведённые строки (`K=PC1 M=PC2`, `K=PC2 M=PC1`) в столбце «Было»
достижимы: синхрон можно включить на устройстве, чьи маршруты уже разошлись.
Именно они проверяют, что ведомое устройство **ставится** на маршрут ведущего
(`set_mouse(mouse_beside(...))`), а не тоглится независимо — независимый
toggle сохранил бы рассинхрон.

### Физические сценарии

- [ ] Зажать `Shift` на ПК1 → переключиться на ПК2 → убедиться, что на ПК1
      `Shift` отпущен (набрать текст на ПК1 и проверить регистр).
- [ ] Зажать левую кнопку мыши на ПК1 → переключиться **клавиатурной** кнопкой
      на ПК2 → убедиться, что на ПК1 кнопка отпущена (выделение не тянется).
      Это главный сценарий: именно он падает, если сцепка положена в `Routes`
      вместо `move_route`.

### Сценарий буфера обмена

- [ ] `Ctrl+C` на ПК1 → одно нажатие переключения → `Ctrl+V` на ПК2.
      Содержимое должно вставиться, второго переключения не потребоваться.
