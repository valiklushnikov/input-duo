# Duo Input: прошивки и Windows-конфигуратор — техническая спецификация MVP

Дата: 2026-08-25  
Статус: согласованный дизайн, ожидает финального просмотра перед планом реализации

## 1. Назначение

Duo Input — автономный переключатель одной проводной USB-клавиатуры и одной проводной USB-мыши между двумя компьютерами. Устройство позволяет:

- независимо направлять клавиатуру на ПК1, ПК2 или одновременно на оба компьютера;
- направлять мышь только на один компьютер: ПК1 или ПК2;
- переключать мышь клавишей клавиатуры или доступной кнопкой мыши;
- переназначать клавиши и кнопки мыши;
- выполнять автономные макросы без постоянно запущенной программы;
- хранить до восьми профилей в устройстве;
- настраивать устройство из Windows-программы через ПК1.

Windows-программа предназначена только для настройки, диагностики и записи конфигурации. Обычный ввод, маршрутизация и макросы работают без программы.

## 2. Границы MVP

### 2.1 Входит в MVP

- две платы RP2040-Zero: U1 MAIN и U2 ENDPOINT;
- два CH375B: отдельный USB host для клавиатуры и для мыши;
- прошивки на C++ с Raspberry Pi Pico SDK и TinyUSB;
- Windows 10/11 x64 конфигуратор на Python 3.12 и PySide6 Widgets;
- стандартный HID-выход к ПК1/ПК2, пригодный для Windows, macOS и Linux; настраивать устройство в MVP можно только при Windows 10/11 на ПК1;
- сборка программы Nuitka в режиме `standalone`;
- обычный Windows-установщик, собранный поверх Nuitka-артефакта;
- конфигурирование только через U1 и ПК1;
- восемь автономных профилей;
- стандартные проводные USB HID-клавиатуры и мыши;
- клавиатурные, текстовые, задерживающие, маршрутные и мультимедийные шаги макросов;
- ручное обновление обеих прошивок через UF2.

### 2.2 Не входит в MVP

- настройка через ПК2;
- сетевой аккаунт, облачная синхронизация или телеметрия;
- Bluetooth и беспроводное управление;
- обновление прошивок из конфигуратора;
- USB hubs;
- гарантированная поддержка игровых устройств, vendor-specific RGB, встроенной памяти периферии и составных беспроводных ресиверов;
- циклы, ветвления, условия, переменные и запуск Windows-программ из макроса;
- выполнение макросов на стороне Windows;
- одновременная передача движения мыши на два ПК;
- автоматическое изменение раскладки операционной системы;
- Linux- или macOS-версия конфигуратора в первом релизе.

## 3. Аппаратная привязка прошивок

Спецификация опирается на монтажные документы `HS005_BOARD1_SOLDERING_GUIDE.md` и `HS005_BOARD2_RP2040_SOLDERING_GUIDE.md`.

### 3.1 U1 MAIN

| Назначение | GPIO U1 | Интерфейс |
|---|---:|---|
| KBD CH375 RXD | GP0 | UART0 TX |
| KBD CH375 TXD | GP1 | UART0 RX |
| KBD CH375 INT | GP2 | GPIO interrupt |
| Mouse CH375 RXD | GP4 | UART1 TX |
| Mouse CH375 TXD | GP5 | UART1 RX |
| Mouse CH375 INT | GP6 | GPIO interrupt |
| TXS0108E OE | GP7 | GPIO output |
| U2 → U1 | GP8 | SPI1 RX/MISO |
| U2 CS | GP9 | SPI1 CSn |
| U2 SCK | GP10 | SPI1 SCK |
| U1 → U2 | GP11 | SPI1 TX/MOSI |
| SW1 | GP14 | GPIO input pull-up |
| SW2 | GP15 | GPIO input pull-up |

U1 подключён USB-C к ПК1. Он является единственным владельцем конфигурации, профилей, маршрутов и состояния макросов.

SW1 является аварийным аппаратным Toggle Mouse Route. SW2 коротким нажатием выполняет Stop and Release All. Удержание SW2 не менее пяти секунд используется как физическое подтверждение Factory Reset. Эти две функции не переназначаются в MVP и остаются доступными при повреждённой пользовательской конфигурации.

### 3.2 U2 ENDPOINT

| Назначение | GPIO U2 | Интерфейс |
|---|---:|---|
| U1 → U2 | GP8 | SPI1 RX/MOSI |
| U1 CS | GP9 | SPI1 CSn |
| U1 SCK | GP10 | SPI1 SCK |
| U2 → U1 | GP11 | SPI1 TX/MISO |

U2 подключён USB-C к ПК2. Он не хранит пользовательские профили, не исполняет макросы и не предоставляет интерфейс конфигурации.

## 4. Общая архитектура

```text
USB Keyboard → CH375 KBD ┐
                         ├→ U1 MAIN → USB HID + CDC → PC1
USB Mouse    → CH375 MS  ┘       │
                                 └→ SPI → U2 ENDPOINT → USB HID → PC2
```

U1 выполняет пять последовательных этапов:

1. получает сырые отчёты CH375;
2. нормализует их в события и полные состояния;
3. применяет активный профиль и назначения;
4. выполняет маршрутизацию и макросы;
5. формирует независимые HID-состояния ПК1 и ПК2.

U2 принимает только проверенные выходные состояния и относительные события мыши. При потере U1 он самостоятельно переводит все HID-выходы ПК2 в отпущенное состояние.

## 5. Архитектура U1

### 5.1 Core 1: физический ввод и логика

Core 1 содержит:

- `Ch375KeyboardDriver`;
- `Ch375MouseDriver`;
- `HidDescriptorParser` для поддерживаемого подмножества HID;
- `InputNormalizer`;
- `BindingEngine`;
- `MacroScheduler`;
- `ProfileRuntime`.

Прерывания INT обоих CH375 только выставляют атомарные признаки готовности. Чтение UART, команды CH375, разбор дескрипторов и HID-отчётов не выполняются в ISR.

Core 1 создаёт фиксированные `OutputCommand` и помещает их в lock-free SPSC-очередь. В realtime-пути запрещено динамическое выделение памяти.

### 5.2 Core 0: USB, выходы, SPI и конфигурация

Core 0 содержит:

- TinyUSB device task для ПК1;
- `HidStateManager`, единолично владеющий состояниями ПК1 и ПК2;
- SPI master link к U2;
- USB CDC protocol service;
- валидатор бинарной конфигурации;
- Flash A/B storage manager;
- watchdog и диагностику.

Только Core 0 вызывает функции TinyUSB HID и меняет выходное HID-состояние. Это исключает одновременные изменения отчётов из разных контекстов.

### 5.3 Смена активной конфигурации

После успешного COMMIT Core 0:

1. сообщает Core 1 о подготовке новой конфигурации;
2. дожидается безопасной границы обработки;
3. выполняет Release All для обоих ПК;
4. атомарно меняет указатель активного профиля;
5. подтверждает новую runtime-конфигурацию Core 1;
6. возобновляет обработку физических событий.

Удерживаемые в момент смены клавиши не синтезируются заново. Пользователь должен отпустить и повторно нажать их.

## 6. Архитектура U2

U2 использует Core 0 для:

- SPI slave;
- проверки magic, версии, длины, sequence и CRC-16;
- очереди относительного движения мыши;
- TinyUSB Keyboard, Mouse и Consumer Control;
- heartbeat watchdog;
- формирования статусного ответа U1.

Core 1 U2 в MVP не используется и зарезервирован.

U2 не исполняет команды, не предусмотренные текущей major-версией протокола. Сто миллисекунд без валидного кадра приводят к Release All, очистке очереди движения и установке ошибки link timeout. После восстановления handshake работа возобновляется автоматически, но старые нажатия и движения не воспроизводятся.

## 7. USB-интерфейсы к компьютерам

### 7.1 U1 на ПК1

U1 является составным USB device:

- HID Keyboard Boot/Report: до шести обычных клавиш одновременно плюс modifiers;
- HID Mouse: X/Y, вертикальное и горизонтальное колесо, пять кнопок;
- HID Consumer Control: стандартные мультимедийные usages;
- CDC ACM: конфигурация и диагностика.

### 7.2 U2 на ПК2

U2 предоставляет:

- тот же HID Keyboard;
- тот же HID Mouse;
- тот же HID Consumer Control;
- без CDC.

### 7.3 Идентификация

- U1 и U2 имеют разные product strings;
- USB serial number формируется из уникального RP2040 chip ID;
- VID/PID задаются build-time конфигурацией;
- коммерческий релиз запрещён до получения законно используемого VID/PID;
- конфигуратор ищет только U1 по VID/PID, product identity и CDC-интерфейсу.

Remote Wakeup в MVP выключен.

## 8. Совместимость входной USB-периферии

Гарантированный класс MVP:

- одна проводная USB HID-клавиатура на клавиатурном CH375;
- одна проводная USB HID-мышь на мышином CH375;
- Boot Protocol в приоритете;
- распространённые простые HID report descriptors как расширение совместимости.

Прошивка читает device, configuration, interface, HID и endpoint descriptors, выбирает подходящий интерфейс и сохраняет:

- VID/PID;
- количество доступных кнопок;
- hash дескриптора;
- выбранный protocol/interface;
- причину отказа при несовместимости.

Не гарантируются USB hubs, vendor-specific endpoints, сложные игровые NKRO-форматы, RGB, составные беспроводные ресиверы и устройства, требующие собственного драйвера.

Выход на ПК ограничен 6KRO. При попытке макроса превысить шесть обычных одновременно удерживаемых клавиш макрос аварийно завершается, созданные им удержания отпускаются, а физические удержания сохраняются.

## 9. Модель событий

Нормализованные типы входа:

- `KeyDown` / `KeyUp`;
- `ConsumerDown` / `ConsumerUp`;
- `MouseButtonDown` / `MouseButtonUp`;
- `MouseMove`;
- `Wheel`;
- `DeviceConnected` / `DeviceDisconnected`.

Для каждого ПК `HidStateManager` раздельно учитывает:

- физические удержания;
- удержания каждого активного макроса;
- modifiers;
- consumer state;
- mouse buttons.

Освобождение клавиши макросом не освобождает ту же клавишу, если пользователь продолжает удерживать её физически.

## 10. Маршруты

### 10.1 Клавиатура

Глобальный `KeyboardRoute`:

- `PC1`;
- `PC2`;
- `BOTH`.

### 10.2 Мышь

Глобальный `MouseRoute`:

- `PC1`;
- `PC2`.

Режим одновременной передачи движения мыши на оба ПК отсутствует.

### 10.3 Безопасная смена

При изменении маршрута прошивка:

1. выпускает затронутые клавиши/кнопки на старой цели;
2. очищает накопленное относительное движение для старой цели;
3. меняет маршрут;
4. применяет новый маршрут только к последующим новым нажатиям и движениям.

Удерживаемое нажатие не переносится на новый ПК.

## 11. Профили и назначения

U1 хранит восемь профилей. Каждый профиль содержит:

- ID 1…8;
- имя до 48 Unicode-символов;
- цвет интерфейса;
- стартовый KeyboardRoute;
- стартовый MouseRoute;
- раскладку текстовых шагов по умолчанию;
- до 128 назначений;
- до 32 макросов.

Триггер назначения:

- одна клавиша клавиатуры с необязательными условиями Ctrl/Shift/Alt/Win;
- одна реально обнаруженная кнопка мыши 1…5.

Modifier-условия не подавляются заранее: `Replace` подавляет основную trigger-клавишу, а modifiers продолжают следовать обычному маршруту.

Режим назначения:

- `Replace`: основная trigger-клавиша или кнопка не передаётся как исходное действие;
- `Add`: физическое событие немедленно проходит по обычному маршруту, а действие запускается дополнительно.

Удержание триггера запускает действие один раз. Повторный запуск разрешён только после зарегистрированного отпускания.

Один и тот же точный триггер не может иметь два назначения в одном профиле. Конфигуратор блокирует запись конфликтующей конфигурации.

## 12. Переключение мыши

Команду управления MouseRoute можно назначить:

- на клавишу клавиатуры;
- на сочетание основной клавиши с modifiers;
- на любую доступную кнопку мыши, объявленную и обнаруженную прошивкой.

Действия:

- `TOGGLE_MOUSE_ROUTE`;
- `SET_MOUSE_ROUTE_PC1`;
- `SET_MOUSE_ROUTE_PC2`.

В одном профиле разрешено несколько маршрутных назначений, например:

- F12 → Toggle;
- Mouse Button 4 → PC1;
- Mouse Button 5 → PC2.

Если после замены мыши назначенная кнопка отсутствует, профиль остаётся валидным, но конфигуратор показывает предупреждение совместимости. Назначение не срабатывает до подключения мыши с такой кнопкой.

## 13. Макросы

### 13.1 Исполнитель

- одновременно исполняется один макрос;
- до четырёх следующих запусков находятся в FIFO;
- пятый ожидающий запуск отклоняется с диагностикой queue full;
- физический ввод продолжает работать во время макроса;
- никакие пользовательские задержки не реализуются через блокирующий `sleep`/`delay`;
- остановка, ошибка или смена профиля освобождают только удержания, созданные прерванным макросом.

### 13.2 Цель

Макрос имеет `TargetMode`:

- `INHERIT`: текущий KeyboardRoute;
- `PC1`;
- `PC2`;
- `BOTH`.

Фиксированная цель макроса действует только на данный запуск и не меняет глобальный маршрут. Маршрут изменяют только специальные route steps.

### 13.3 Шаги MVP

| Шаг | Параметры | Поведение |
|---|---|---|
| `KEY_TAP` | usage + modifiers | нажать, выдержать стандартный tap interval, отпустить |
| `KEY_DOWN` | usage | добавить удержание макроса |
| `KEY_UP` | usage | убрать удержание макроса |
| `CONSUMER_TAP` | consumer usage | стандартная media key |
| `TEXT` | скомпилированная HID-последовательность | ввести текст выбранной раскладкой |
| `DELAY` | fixed либо inclusive random range, 0…60000 мс | неблокирующее ожидание |
| `SET_KEYBOARD_ROUTE` | PC1/PC2/BOTH | изменить глобальный маршрут клавиатуры |
| `SET_MOUSE_ROUTE` | PC1/PC2/TOGGLE | изменить глобальный маршрут мыши |
| `SET_PROFILE` | 1…8 | безопасно активировать другой профиль |

Лимиты:

- до 64 шагов в макросе;
- до 1024 Unicode-символов в одном исходном Text-шаге;
- не более 32 макросов в профиле.

### 13.4 Текст и раскладки

Поддерживаются:

- English US;
- Русская;
- Украинская.

JSON-проект хранит Unicode-текст и выбранную раскладку. Windows-программа при компиляции переводит текст в последовательность HID usages и modifiers. Неподдерживаемый символ является ошибкой с указанием макроса, шага и позиции.

Перед запуском макроса на целевом ПК должна быть активна та же раскладка. Прошивка не определяет и не переключает раскладку ОС.

## 14. Бинарная конфигурация и Flash

RP2040-Zero имеет 2 МиБ Flash. Карта U1:

| Область | Смещение | Размер |
|---|---:|---:|
| Firmware | `0x000000` | 1024 КиБ |
| Config A | `0x100000` | 384 КиБ |
| Config B | `0x160000` | 384 КиБ |
| Service | `0x1C0000` | 256 КиБ |

Все границы кратны 4 КиБ. Максимальный бинарный config package — 360 КиБ. Остаток слота используется для заголовка, hash, generation counter и выравнивания.

В SRAM загружается только активный профиль и глобальный индекс конфигурации, а не все восемь профилей целиком.

Каждый config slot содержит:

- magic;
- schema major/minor;
- generation counter;
- payload length;
- SHA-256 payload;
- header CRC-32;
- бинарный payload.

При запуске U1 выбирает валидный слот с максимальным generation counter. Если оба слота повреждены, загружается встроенная factory configuration, все выходы остаются отпущенными и устанавливается диагностический флаг.

## 15. USB CDC протокол Windows ↔ U1

### 15.1 Транспорт

- CDC ACM;
- штатный драйвер Windows 10/11;
- асинхронная работа через `PySide6.QtSerialPort`;
- COBS framing с байтом-разделителем `0x00`;
- полезная нагрузка одного кадра до 1024 байт.

Декодированный кадр:

| Поле | Размер |
|---|---:|
| Magic | 2 байта |
| Protocol major/minor | 2 байта |
| Message type | 1 байт |
| Flags | 1 байт |
| Sequence | 2 байта |
| Payload length | 2 байта |
| Payload | 0…1024 байта |
| CRC-32 | 4 байта |

Sequence связывает один запрос и один ответ. U1 не исполняет два изменяющих состояние запроса одновременно.

### 15.2 Команды

- `HELLO` / `DEVICE_INFO`;
- `GET_STATUS`;
- `GET_ACTIVE_CONFIG_INFO`;
- `READ_CONFIG_BEGIN` / `READ_CONFIG_CHUNK`;
- `WRITE_BEGIN`;
- `WRITE_CHUNK` по 512 байт;
- `WRITE_VERIFY`;
- `WRITE_COMMIT`;
- `WRITE_ABORT`;
- `SET_ACTIVE_PROFILE`;
- `CAPTURE_BEGIN` / `CAPTURE_EVENT` / `CAPTURE_END`;
- `TEST_MACRO` / `STOP_AND_RELEASE_ALL`;
- `GET_DIAGNOSTICS`;
- `FACTORY_RESET_ARM` / `FACTORY_RESET_COMMIT`;
- `PING`.

Factory Reset через CDC завершается только при удержании назначенной физической кнопки устройства, подтверждённом U1.

### 15.3 Транзакционная запись

1. Программа выполняет HELLO и проверяет capabilities.
2. WRITE_BEGIN передаёт полный размер и SHA-256.
3. U1 стирает неактивный слот и создаёт staging transaction.
4. Программа передаёт последовательно пронумерованные chunks.
5. WRITE_VERIFY проверяет структуру, ограничения и hash.
6. WRITE_COMMIT записывает заголовок и generation последними.
7. U1 переключает runtime configuration.
8. Программа читает обратно generation и hash.

Disconnect, timeout, bad chunk, bad hash и WRITE_ABORT не меняют активный слот.

## 16. SPI протокол U1 ↔ U2

### 16.1 Физический режим

- SPI1;
- U1 master, U2 slave;
- начальная частота 1 МГц;
- фиксированный кадр 64 байта;
- polling не реже одного раза в 20 мс и немедленно при наличии данных;
- U2 link timeout 100 мс.

### 16.2 Заголовок

Кадр содержит:

- magic;
- protocol major/minor;
- message type;
- flags;
- sequence;
- payload length;
- payload;
- CRC-16.

Неиспользованные байты фиксированного кадра заполняются нулями и включаются в CRC.

### 16.3 Типы U1 → U2

- `HANDSHAKE`;
- `KBD_STATE`;
- `CONSUMER_STATE`;
- `MOUSE_DELTA`;
- `CONTROL_RELEASE_ALL`;
- `HEARTBEAT`.

`KBD_STATE` передаёт полное состояние клавиатуры, а не только edge event. `MOUSE_DELTA` передаёт относительные `dx`, `dy`, вертикальное и горизонтальное колесо и актуальную маску кнопок.

### 16.4 Ответ U2

Каждая транзакция возвращает:

- last accepted sequence;
- USB mounted/suspended status;
- error flags;
- mouse queue depth;
- protocol version;
- uptime/reset reason при handshake.

### 16.5 Совместимость

- различный protocol major запрещает работу ПК2;
- различный minor разрешает только пересечение capabilities;
- при несовместимости U1 сохраняет работу ПК1, отключает маршрут на ПК2 и сообщает ошибку конфигуратору;
- обновление U1/U2 выполняется вручную через UF2.

## 17. Обработка ошибок и fail-safe

| Ошибка | Обязательная реакция |
|---|---|
| CH375 disconnect | отпустить состояния затронутого устройства на обоих ПК |
| CH375 parse error | отбросить отчёт, записать код, при повторении переинициализировать устройство |
| Core queue overflow | Release All, очистить очередь, выставить fatal runtime error |
| Неверный CDC/SPI CRC | отбросить кадр без действия |
| U2 timeout | U2 и U1 очищают состояние ПК2 |
| USB PC suspend/unmount | не копить относительное движение; корректно восстановить отчёты после mount |
| Macro queue full | отклонить новый запуск, не нарушать текущий макрос |
| Macro runtime error | отпустить только удержания этого макроса и записать диагностику |
| Watchdog reset | начать с полностью отпущенных HID-состояний |
| Config A/B invalid | factory configuration, выходы отпущены, config error |

Watchdog включён на обеих платах. Reset reason и счётчик watchdog сохраняются в служебной области с ограничением частоты записи Flash.

## 18. Windows-конфигуратор

### 18.1 Технологии

- Python 3.12 x64;
- PySide6 Widgets;
- `PySide6.QtSerialPort`;
- pytest и pytest-qt;
- Nuitka `standalone` с плагином PySide6;
- Windows-установщик, рекомендуемый инструмент — Inno Setup;
- права администратора для обычной работы не требуются.

Русский язык интерфейса является языком по умолчанию. Английская локализация входит в MVP; внутренние коды ошибок и форматы проектов от языка интерфейса не зависят.

### 18.2 Слои приложения

```text
UI / ViewModels
    ↓
Domain: profiles, bindings, macros, validation, compiler
    ↓
Device Service: QSerialPort, framing, transactions, connection state
    ↓
Persistence: JSON projects, autosave, settings, diagnostics export
```

Qt widgets не содержат код COBS, CRC, бинарной компиляции или Flash-транзакций. Domain не зависит от Qt widgets и тестируется отдельно.

### 18.3 Экраны

1. **Обзор**: U1/U2, версии, периферия, активные маршруты, активный профиль, использование памяти.
2. **Назначения**: список/карта триггеров, режим Replace/Add, действие или макрос.
3. **Макросы**: пошаговый drag-and-drop редактор, цель, раскладка, валидация.
4. **Мышь**: выбор клавиатурного либо мышиного триггера для Toggle/PC1/PC2.
5. **Профили**: восемь слотов, имя, цвет, копирование, очистка, активация.
6. **Диагностика**: версии, USB identities, descriptor hashes, ошибки, очереди, export ZIP.
7. **Настройки программы**: язык интерфейса, путь проектов, журналирование.

### 18.4 Определение физической клавиши или кнопки

1. Пользователь нажимает «Определить».
2. Программа отправляет CAPTURE_BEGIN с типом keyboard/mouse.
3. U1 продолжает передавать движение мыши и все прочие события, но первое подходящее новое нажатие не выполняет назначение и не отправляется компьютерам.
4. U1 отправляет захваченное нажатие через CDC и автоматически завершает capture mode.
5. Программа показывает HID usage либо button number.
6. Пользователь подтверждает выбор; без нового события CAPTURE_END срабатывает по тайм-ауту 10 секунд.

Список кнопок мыши строится по реально обнаруженным возможностям, а не содержит недоступные Button 4/5 по умолчанию.

### 18.5 Состояния проекта

Интерфейс явно различает:

- локальные несохранённые изменения;
- сохранённый `.duoinput.json` проект;
- конфигурацию, записанную в устройство.

Запись выполняется только кнопкой «Записать в устройство». Перед WRITE_BEGIN программа компилирует все профили, проверяет ошибки и показывает объём пакета.

### 18.6 Файл проекта

- расширение `.duoinput.json`;
- UTF-8;
- обязательный `schema_version`;
- стабильные UUID макросов и назначений;
- исходный Unicode-текст сохраняется без потери;
- неизвестный major schema не открывается на запись;
- старые поддерживаемые minor schemas мигрируются в памяти и сохраняются только после согласия пользователя.

Autosave recovery хранится в `%LOCALAPPDATA%\DuoInput\autosave`. Журналы находятся в `%LOCALAPPDATA%\DuoInput\logs`.

### 18.7 Тестовый запуск макроса

- пользователь явно выбирает ПК1, ПК2 или оба;
- перед запуском показывается предупреждение о генерации реального ввода;
- кнопка `STOP AND RELEASE ALL` доступна всё время выполнения;
- закрытие окна либо потеря CDC отправляет stop, если соединение ещё доступно;
- тест не изменяет сохранённую конфигурацию.

## 19. Диагностика и приватность

U1 сообщает:

- firmware/protocol/schema versions;
- chip ID;
- reset reason и watchdog count;
- CH375 state;
- VID/PID и descriptor hash периферии;
- обнаруженные keyboard/mouse capabilities;
- SPI CRC errors и timeouts;
- текущую и максимальную глубину очередей;
- активный profile ID и маршруты;
- коды последней ошибки каждого подсистемного домена.

Экспортируемый ZIP по умолчанию не содержит исходный текст макросов и полную конфигурацию. Их добавление требует отдельного согласия пользователя в диалоге экспорта.

Программа и прошивки не используют сеть и не собирают телеметрию.

## 20. Безопасность входных данных

- все длины CDC, SPI и binary config проверяются до чтения payload;
- каждый массив имеет compile-time максимум;
- переполнение целых и выход за границы проверяются;
- неизвестные types и flags отклоняются;
- packet/config parsers покрываются fuzz tests;
- realtime paths не используют heap;
- повреждённые данные не должны вызывать HID-действие;
- Factory Reset требует физического подтверждения;
- аутентификация USB в MVP отсутствует: физический доступ к кабелю ПК1 считается доверенной границей.

## 21. Тестирование

### 21.1 Прошивки: unit tests

- COBS и CRC-16/CRC-32;
- все позитивные и негативные варианты frame parser;
- HID report diff;
- Replace/Add;
- маршруты и смена при удержании;
- reference-count/ownership физического и макросного удержания;
- FIFO макросов, задержки, отмена и ошибки;
- US/RU/UA text compiler golden vectors;
- binary config validator;
- Flash A/B generation и recovery;
- сборка U1/U2 UF2.

### 21.2 Конфигуратор

- pytest для Domain, compiler, protocol и persistence;
- pytest-qt для dirty states, экранов, ошибок и блокировки записи;
- эмулятор U1 CDC для timeout, disconnect, bad CRC, retry и commit;
- JSON migration golden files;
- JSON → binary → decode round trip;
- Nuitka standalone smoke test на чистой Windows 10 и Windows 11 VM;
- установка, запуск и удаление установщика.

### 21.3 Hardware-in-the-loop

- две реальные платы U1/U2;
- обрыв и восстановление SPI;
- повреждение CRC и пропуск sequence;
- reset каждой платы отдельно;
- disconnect/reconnect обоих ПК в разном порядке;
- отключение и замена клавиатуры/мыши;
- обрыв питания во время каждого этапа config transaction.

### 21.4 Приёмочные критерии

| Проверка | Критерий |
|---|---|
| Периферия | не менее пяти клавиатур и пяти мышей проходят опубликованную compatibility matrix |
| Переключение | 1000 последовательных переключений без залипаний, двойных срабатываний и самоввода |
| U2 fail-safe | Release All не позднее 100 мс после потери валидного SPI |
| Конфигурация | 100 успешных записей и 20 искусственных обрывов всегда оставляют новую или предыдущую валидную копию |
| Задержка | end-to-end p95 не более 20 мс для клавиатуры и мыши на обоих ПК |
| Плавность | нет пауз движения мыши более 50 мс при нормальной работе |
| Длительная работа | 24 часа без watchdog reset, переполнения очередей и деградации движения |
| Профили | все восемь сохраняются, активируются и переживают полный power cycle |
| Макросы | физический ввод остаётся рабочим, STOP освобождает все созданные макросом удержания |
